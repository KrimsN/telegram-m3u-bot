# telegram-m3u-bot

Telegram-бот: получает пересланное сообщение с видеофайлом (даже размером в несколько ГБ)
и в ответ присылает `.m3u`-плейлист для воспроизведения видео в VLC — без скачивания
и хранения файла на своей стороне.

## Как это работает

Обычный Telegram Bot API отдаёт файлы только до 20 МБ, поэтому бот подключается к Telegram
напрямую по протоколу MTProto через [`kurigram`](https://github.com/KurimuzonAkuma/kurigram)
(поддерживаемый форк Pyrogram). Видео нигде не сохраняется: `.m3u`-плейлист содержит ссылки
на собственный HTTP-эндпоинт бота, который на лету стримит чанки видео прямо из Telegram
через `aiohttp` (с поддержкой `Range`-заголовков — так VLC может перематывать видео).

## Стек

- Python >= 3.13, зависимости и виртуальное окружение — через `uv` (`pyproject.toml`, `uv.lock`).
- [`kurigram`](https://pypi.org/project/kurigram/) — MTProto-клиент бота.
- `aiohttp` — сервер, отдающий видео чанками.
- `tgcrypto`, `uvloop` — ускорители (только Linux, см. ниже).
- Точка входа: `src/main.py`.

## Структура проекта

```
src/
  main.py        # запуск бота и HTTP-сервера
  config.py      # конфигурация из переменных окружения
  bot.py         # обработчик пересланных видео, сборка m3u-плейлиста
  streaming.py    # aiohttp-эндпоинт, стримит видео из Telegram по частям
```

## Конфигурация

Переменные окружения (см. `.env.example`):

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | данные приложения с [my.telegram.org](https://my.telegram.org) — нужны для MTProto |
| `PUBLIC_BASE_URL` | публичный адрес, по которому доступен HTTP-сервер бота (используется в ссылках m3u-плейлиста), без слэша в конце |
| `STREAM_HOST`, `STREAM_PORT` | адрес и порт, на которых слушает стриминг-сервер (по умолчанию `0.0.0.0:8080`) |

Локально переменные читаются из `.env` (не коммитится, см. `.gitignore`).

## Локальный запуск

```bash
uv sync              # установить зависимости
uv run src/main.py   # запустить бота
uv add <package>      # добавить зависимость
```

`tgcrypto` и `uvloop` собираются из исходников и требуют компилятор — на Windows их сборка
пропускается (зависимости помечены `sys_platform == 'linux'`), бот работает и без них, просто
чуть медленнее на шифровании MTProto.

## Запуск в Docker

```bash
docker compose up --build
```

В контейнере (Linux) `tgcrypto` и `uvloop` собираются и устанавливаются, ускоряя работу бота.
Порт `8080` пробрасывается наружу — для локального теста укажите в `.env`:

```
PUBLIC_BASE_URL=http://localhost:8080
```

## Replit

- На Replit переменные окружения задаются через Secrets, а не `.env` — при деплое перенести
  туда `TELEGRAM_BOT_TOKEN`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и `PUBLIC_BASE_URL`.
